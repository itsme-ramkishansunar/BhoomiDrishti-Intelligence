# U71.9 — Final Map Runtime + New Project Hardening

- New projects with a known district and no explicit coordinate now receive a deterministic district-centroid demonstration point, explicitly labelled `DISTRICT_CENTROID` / `DEMO_APPROXIMATE`.
- Projects with a known supported state but no district coordinate can use a deterministic state-centroid fallback; the location remains explicitly approximate.
- India GIS boundary validation remains mandatory; out-of-India coordinates are rejected.
- Risk Map automatically fits when its plotted dataset changes, including newly-created projects and location updates.
- Added basemap fallback from OpenStreetMap tiles to CARTO when repeated tile failures occur.
- Resolve-missing now reports actual success counts and never claims failed geocoding succeeded.
- Structured project imports require a district instead of silently inserting a placeholder that cannot be mapped safely.
- Legacy schematic `map_x/map_y` values are no longer sent by the Add Project UI; latitude/longitude and backend GIS provenance are authoritative.
- Added isolated map runtime smoke coverage for new-project mapping, provenance transitions, boundary rejection, tile fallback and auto-fit behavior.
- Existing persistent database, intake, predictive-lab governance, connector, RBAC and project-lifecycle safeguards are preserved.
