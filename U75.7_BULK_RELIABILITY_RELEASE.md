# BHOOMIDHRISHTI U75.7 — Bulk Reliability & Recovery

Version: `1.0.27-u75.7-bulk-reliability`

## What this release fixes

- Bulk dataset forensic analysis now runs through an in-process Node runtime first for CSV, TSV, JSON and NDJSON uploads.
- XLSX continues to use the existing Python standard-library inspector.
- Windows Python launcher/PATH issues no longer block ordinary CSV/JSON bulk intake.
- Failed ingestion runs remain safely stored and can be retried without re-uploading the file.
- Added diagnostics endpoint for failed runs.
- Data Integration Center exposes **Retry analysis** and **View diagnostics** for failed runs.
- Existing governed promotion flow remains unchanged: profile → validate → match → conflict review → evidence → explicit promotion → project bootstrap → unified snapshot → features → operational intelligence.
- Existing non-empty authoritative project values remain protected during acknowledged conflicts.
- Predictive production promotion remains governed and blocked until its existing historical-data/calibration gates are satisfied.

## New API contracts

- `POST /api/data-ingestion/runs/:id/retry-analysis`
- `GET /api/data-ingestion/runs/:id/diagnostics`

## Safety

Uploading a dataset does not make it government-authoritative. Promotion remains an explicit administrator workflow. Failed analysis does not train, alter or promote a model.

The release does not include or reset the persistent application database.
